# Interview — 多智能体协作面试系统

> **JD 进，面试官出，聊完给报告。**

输入一份 **JD（职位描述）**，系统自动解析技能要求、检索公司业务背景、生成专属**面试官 Agent**；上传**简历**后面试官围绕简历提出第一个问题，随后按一套**面试环节剧本**（项目深挖 → 大模型八股 → 计算机基础 → 手撕算法 → 反问）逐轮推进，并**动态调整问题难度**；全程落库记录，结束时自动产出**候选人评估报告**（Markdown，含对话形式的完整记录）。

技术栈：**Python 3.10+ · FastAPI · SQLite · OpenAI 兼容 API**（DeepSeek / Moonshot / 通义 / Ollama 网关等均可）。前端为纯 HTML/JS/CSS 的单页聊天界面，无需构建。

## 快速开始

```bash
# 1. 安装依赖
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt          # 开发/测试再加 requirements-dev.txt

# 2. 配置模型（必填：面试依赖真实大模型，无离线演示模式）
cp .env.example .env
#    编辑 .env，填入 OPENAI_API_KEY 等（也可启动后在前端 ⚙ 设置里填）

# 3. 启动
./scripts/start.sh          # 或 .venv/bin/python -m web.server
# 浏览器打开 http://127.0.0.1:8000
```

> 端口被占用时：`PORT=8080 .venv/bin/python -m web.server`
> 首次体验可直接点击界面上的 **“填入示例 JD”**。

### 一场面试长什么样

1. **贴 JD** → 生成面试官（画像 + 开场白），并规划出本次面试的**环节剧本**；
2. **交简历**（点击/拖拽上传 `txt / md / pdf / docx`，≤10MB）→ 面试官基于简历内容抛出**第一个问题**；
3. **逐轮作答** → 每轮评分调档，面试官在**当前环节内**追问或换考点，环节满轮数/答得好就推进到下一环；
4. **进入最后一环「反问」** → 面试官把提问权交给候选人（“你有什么想问我的吗？”），**不会**再出技术题；
5. **结束** → 自动生成评估报告（四维打分 + 亮点证据 + 建议 + 录用建议 + 对话形式的完整记录）。

**环节剧本**由 LLM 按职级与岗位类型生成（AI/算法岗含「大模型基础」、资深岗以系统设计为主），形如：

```
项目深挖(3-5) → 大模型基础(3-4) → 计算机基础(2-3) → 手撕算法(1-2) → 反问环节(1-2)
```

每个环节带题型与 `min_turns / max_turns`；模型没给或给坏时按职级 + 是否 AI 岗套**确定性模板**兜底。

**没有演示模式**：所有面试与报告均由真实 LLM 驱动，未配置 `OPENAI_API_KEY` 时服务仍可启动，但页面会弹窗提醒先填写 API Key（点右上角 **⚙ 设置** 或写 `.env`），未配置时发起面试会直接报错。

### 在前端配置 LLM（无需改文件 / 重启）

点右上角 **⚙ 设置** 打开“模型设置”弹窗，可随时填写/切换 **API Key、Base URL、模型名**，保存后对后续会话即时生效（当前面试的进行中轮次也会切换）：

- 内置 **OpenAI / DeepSeek / Moonshot** 快捷填入与常见模型下拉提示；
- **测试连接** 会先用当前输入的真实调用验证连通性（不保存）；
- 需要重置时勾选“清除已配置的 Key”即可回到未配置状态（页面会再次弹窗提醒填写）；
- 勾选“写入项目 `.env`”则明文持久化（下次启动仍生效），否则仅本次进程内生效。

API Key 只在保存时写入本机（`.env` 或内存），**后端永不回显**（GET 只返回 `api_key_set`）。

### 可选：按公司/岗位定制面试风格（面经检索）

生成面试官时，系统会针对 **公司 + 岗位** 全网搜索 **20+ 篇公开面经**（面试经验帖），交给 LLM 总结成该岗位真实面试风格（轮次结构、考察侧重、氛围），并让画像与面试官贴合该风格——不同公司的面试风格因此不同。

- 在 [Tavily](https://app.tavily.com) 免费申请 API Key（每月 1000 次，无需绑卡），填入 `.env` 的 `TAVILY_API_KEY`；
- 风格按 `(公司, 岗位)` 缓存进 SQLite（`interview_styles` 表，职级前后缀视为同一岗位，如“高级后端工程师”与“后端工程师”复用同一风格）；后续同公司同岗位的新面试直接复用缓存，**不重复搜索**；
- 未配置 Key / 搜索失败 / 结果过少时**自动降级**为仅基于 JD + Wikipedia 的通用画像，不影响面试；
- 可在 `GET /api/health` 的 `style_search` 字段确认是否已启用。

### 模型配置（兼容任何 OpenAI 风格端点）

| 环境变量 | 说明 | 示例 |
| --- | --- | --- |
| `OPENAI_API_KEY` | API Key（必填；留空则服务可启动但无法面试） | `sk-...` |
| `OPENAI_BASE_URL` | 端点地址 | `https://api.deepseek.com/v1` |
| `OPENAI_MODEL` | 模型名 | `deepseek-chat` / `gpt-4o-mini` |
| `DB_PATH` | SQLite 存储路径 | `data/interview.db` |
| `WIKI_LANG` | 公司背景检索语言 | `zh` |
| `TAVILY_API_KEY` | 面经检索（可选，见下） | `tvly-...` |
| `MAX_TURNS` | 面试最多提问轮数 | `12` |
| `PORT` / `HOST` | 服务监听 | `8000` / `127.0.0.1` |

> `.env` 是初始值；运行中可在前端 ⚙ 设置里覆盖（也可选择写回 `.env` 持久化）。

## 架构与模块（对应设计文档）

```
                      用户 / 候选人（Web 聊天界面）
                                    │
                        ┌───────────▼───────────┐
                        │  Orchestrator 编排层    │  初始化 → 面试 → 收尾 → 报告
                        └───┬───────┬────────┬──┘
              ┌─────────────▼───┐ ┌──▼───────┐ ┌─▼──────────────┐
              │ Interviewer      │ │ 难度控制器 │ │  Recorder      │
              │ Builder (JD 解析 │ │ (独立评分, │ │ (SQLite 会话/   │
              │  公司检索→画像)   │ │  规则调档) │ │  消息/报告落库) │
              └─────────────────┘ └──────────┘ └────────────────┘
                       ▲                            │
                       │                            ▼
              ┌────────┴─────────┐      ┌──────────────────────┐
              │ Evaluator 评估报告 │◄─────│ Interviewer Core     │
              │ (四维打分+评语+建议) │      │ (多轮记忆·追问·难度档位) │
              └──────────────────┘      └──────────────────────┘
```

| 目录 / 文件 | 职责 |
| --- | --- |
| `interview/jd_parser.py` | 解析 JD：硬/软技能、年限、职级、考察点（LLM 解析 + 正则兜底） |
| `interview/researcher.py` | 公司/部门背景检索（Wikipedia，免 Key）；失败自动降级为“仅基于 JD 的通用面试官” |
| `interview/style_researcher.py` | 公司+岗位面经检索（Tavily，可选）+ LLM 总结面试风格；`(公司,岗位)` 缓存跨会话复用；失败自动降级 |
| `interview/models.py` | 共享数据结构：`InterviewSection` / `InterviewPlan`（环节剧本）、AI 岗位识别与确定性 plan 模板 |
| `interview/builder.py` | **Interviewer Builder**：生成面试官画像（风格/语气/考察重点/开场白，可参考面经风格）与**面试环节剧本** `interview_plan` |
| `interview/difficulty.py` | **难度控制器**：独立评分员给回答打 1–5 分并抽取关键事实；规则调档（连续 2 轮优秀升档 / 连续 2 轮卡壳降档并切换题型），档位 L1 概念 → L2 应用 → L3 深度设计 |
| `interview/interviewer.py` | **面试官 Core**：按当前环节与难度档位出题/追问，口语化、一次只问一个问题，可回引“你刚才提到……”；进入「反问」环节时确定性地把提问权交给候选人 |
| `interview/evaluator.py` | **评估报告生成**：技术深度 / 逻辑表达 / 岗位匹配度 / 沟通风格四维打分 + 亮点证据 + 建议 + 录用建议，输出结构化 Markdown |
| `interview/recorder.py` | **Recorder**：SQLite 持久化会话、每轮消息（含时间戳/难度/质量分）、报告，支持回溯审计 |
| `interview/orchestrator.py` | **编排层**：会话生命周期、消息协议、候选人“申请结束/达到目标题量”自动收尾 |
| `interview/llm.py` | LLM 适配层：OpenAI 兼容客户端；运行时热切换（未配置时显式报错，无 Mock/演示模式） |
| `web/server.py` + `web/static/` | FastAPI 接口 + 聊天 UI（粘贴 JD → 对话 → 报告） |
| `tests/` | 35 个单元/端到端测试，离线可跑 |

设计要点落实：
- **面试官与评分解耦**：提问与质量评分是两个独立模型调用，评分员只输出分数与事实，不参与出题。
- **动态难度**：`DifficultyController` 只做档位路由与切换信号，题目/追问由面试官按档位生成。
- **对话记忆**：上下文窗口 + 关键事实独立抽取（`facts`，如“候选人熟悉 Redis 缓存淘汰”），长对话不丢关键信息。
- **环节剧本（scripted sections）**：`InterviewPlan` 把面试拆成有序环节，`plan_state` 按 `min/max_turns` 与作答质量**确定性推进**，面试官只在当前环节的题型内出题。
- **反问环节硬交接**：进入最后一环时不再经过 LLM，直接输出“你有什么想问我的吗？”，从机制上杜绝面试官在该环节继续出技术题。
- **可插拔检索 + 优雅降级**：JD 解析失败→正则兜底；公司检索失败→仅基于 JD 组织面试。模型出题/评分/报告失败会**显式报错**而非静默用脚本内容替代。

## 交互流程

```
[1] 用户粘贴 JD ──► [2] Builder：解析 → 检索公司背景 → 生成面试官画像 + 环节剧本
                        │
[3] 面试官开场自我介绍（预告环节安排）◄──────┘
        │
[4] 上传简历 ──► 面试官基于简历抛出第一个问题
        │
[5] 多轮循环：候选人作答 → 评分调档 → 在当前环节内追问/换考点 → 满足条件则推进环节 →（重复）
        │              （AI 岗含「大模型基础」环节；最后一环「反问」把提问权交给候选人）
[6] 达到目标题量 / 候选人申请结束
        │
[7] Recorder 汇总 → Evaluator 生成 Markdown 报告 → 前端展示（含对话形式的完整记录）
```

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/sessions` | 提交 `{"jd": "..."}`，创建会话并返回面试官画像（含环节剧本）与开场白 |
| `POST` | `/api/sessions/{id}/resume` | 上传简历文件（multipart，`txt/md/pdf/docx`），提取文本并返回基于简历的第一问 |
| `POST` | `/api/sessions/{id}/answer` | 提交 `{"answer": "..."}`，返回追问、当前**环节**/轮次、难度档位/信号、质量分；候选人可说“结束面试” |
| `POST` | `/api/sessions/{id}/end` | 结束面试，返回 `report_md` 与 `report_html` |
| `GET` | `/api/sessions` | 会话列表（`limit`/`q` 按岗位/公司/名称搜索），供左侧栏展示 |
| `GET` | `/api/sessions/{id}` | 会话详情 + 完整消息 + 报告（已结束时）；进行中的会话可续面 |
| `POST` | `/api/sessions/{id}/rename` | 重命名会话 `{"title": "..."}` |
| `DELETE` | `/api/sessions/{id}` | 删除会话及其全部消息 |
| `GET` | `/api/health` | 健康检查 / 是否已配置 LLM / 模型名 |
| `GET` | `/api/llm/config` | 读取当前 LLM 配置（API Key 仅回传是否已设置） |
| `POST` | `/api/llm/config` | 运行时切换 LLM（`api_key`/`base_url`/`model`，`null`=保持不变，`api_key:""`=清除 Key 回到未配置；`persist` 可选写回 `.env`） |
| `POST` | `/api/llm/test` | 用给定的凭据做一次真实小调用验证连通性（不保存） |
| `POST` | `/api/llm/models` | 拉取当前账号可用模型列表（不保存） |

## 测试

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests -q        # 35 passed，无需 API Key（离线可跑）
```

覆盖：JD 解析（正则与脚本化假 LLM 两路）、难度调档规则与边界、停止语意图识别、**环节剧本（plan 模板 / 解析 / 状态机推进）**、全生命周期编排（升级/降级/收尾/报告落库/回溯）、**反问环节交接提问权**、**报告完整对话记录的对话化渲染**、HTTP 接口全流程、简历上传流程、侧栏会话管理（列表/搜索/重命名/删除）、LLM 运行时热切换与未配置时的报错引导、面经风格检索的缓存命中/键归一化/优雅降级/画像注入。

> 测试通过 `DB_PATH` 环境变量使用各自独立的临时 SQLite 库，不会污染 `data/interview.db`。
